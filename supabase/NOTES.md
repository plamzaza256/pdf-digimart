## 2. ข้อสมมติค่าเริ่มต้น (ตอบข้อ 7 — ระบุชัด ไม่เดา)

1. **ไม่มีไฟล์ PDF จริงอยู่ในโปรเจกต์เลย** (ยืนยันแล้วจาก audit: glob `**/*.pdf` ไม่เจอ) ดังนั้น `document_language` ของทุกแถวจึงเป็นเพียง "ค่าเริ่มต้นเพื่อทดสอบ" ไม่ใช่ผลตรวจไฟล์จริง
2. แถว mock เดิมให้ `document_language='th'` เพราะชื่อ+คำอธิบายเขียนภาษาไทย — **แต่กำกับ `language_verified=false` ทุกแถว** เพื่อไม่ให้ดูเหมือนผ่านการตรวจแล้ว
3. กฎก่อนขายจริง: แอดมินต้องเปิดไฟล์ PDF ตรวจภาษาจริง แล้วค่อยตั้ง `language_verified=true` (ทำผ่านหน้าแอดมินในอนาคต ไม่ใช่รอบนี้)
4. `description_language` เริ่มต้น `'th'` ตามหน้าร้านปัจจุบันที่เป็นภาษาไทย
5. `document_type` ของแถวเดิมเป็นการตีความจากชื่อ/คำอธิบาย (ตารางข้อ 1) ไม่ใช่ข้อเท็จจริงจากไฟล์
6. `rating`/`sales` ใน seed เป็นตัวเลข placeholder เดิมจาก mock — รีเซ็ตเป็น 0 เมื่อขึ้นขายจริง
7. แถว `[SAMPLE]` ทั้งสองมีไว้ดูโครงฟิลด์เท่านั้น ห้ามนำไปแสดงว่าขายจริง (มี prefix + `is_sample=true` สองชั้น)

## 3. การค้นหา/กรองในอนาคต (ตอบข้อ 6)

- กรองตามภาษาเอกสาร: `WHERE document_language = 'en'` (ใช้ index `idx_products_doc_lang_type`)
- กรองตามประเภท: `WHERE document_type = 'worksheet'` (index เดียวกัน)
- ค้นหาข้อความ 2 ภาษา: `title ILIKE '%grammar%'` (index trigram `idx_products_title_trgm`) — รองรับสะกดบางส่วนทั้งไทย/อังกฤษ
- ค้นหาแท็ก: `WHERE tags && ARRAY['toeic','english']` (index GIN `idx_tags_gin`) — แท็กไทย+อังกฤษอยู่ในอาเรย์เดียวกันได้เลย
- ตัวอย่าง query ผสม (หน้าร้านในอนาคต): เลือก `document_language='en'` + `document_type IN ('exam','worksheet')` + คำค้น `'tense'` ในคราวเดียวได้โดยไม่ต้องเปลี่ยน schema

## 4. ความเข้ากันได้กับเว็บเดิม (ตอบข้อ 9)

- คอลัมน์ใหม่ทั้งหมดเป็น **ส่วนเสริม (additive)** — `id/title/.../category` เดิมอยู่ครบ ไม่เปลี่ยนชื่อ/ชนิด
- `category` ('หนังสือ/เอกสาร/ข้อสอบ') ยังอยู่เหมือนเดิม หน้า Shop ปัจจุบันทำงานต่อได้โดยไม่แก้
- ฝั่ง TypeScript อนาคต: เติม optional fields ใน `Product` (`document_language?` ฯลฯ) แล้วค่อยเปลี่ยนเป็น required หลัง seed ครบ — ไฟล์ `src/` รอบนี้ไม่ถูกแตะ
- ตัวกรองภาษา/ประเภทใน UI เป็นงานรอบหน้า (เพิ่ม dropdown 2 ตัวผูกกับคอลัมน์ใหม่) รอบนี้ห้ามเปลี่ยน UI
